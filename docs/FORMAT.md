# 小米相机预设 zip 格式规范

本文档由 **64 个真实预设样本**的结构分析得出：48 个来自社区分享的预设包，16 个来自小米社区发布的官方风格预设。

小米从未公开过此格式。网上所有教程只讲导入步骤，本文档是目前唯一一份描述其内部结构的中文资料。

- 分析时间：2026-11
- 实测机型：Xiaomi 17 Pro / HyperOS 4
- 可信度标注：**实测** = 已在自己的设备上导入并逐项核对界面显示值；**推断** = 结构分析得出但未单独验证

---

## 一、整体结构

一个预设 zip 包含 **19 个条目，全部为 0 字节的空文件**。所有信息编码在**文件名**里，没有任何文件内容。

```
Manual_xuanyuan_1743125120377_阴天柔和风.zip
├── p_pref_camera_cv_type_key_1              (0 字节)
├── p_pref_camera_autoexposure_key_1         (0 字节)
├── p_pref_qc_camera_exposuretime_key_0      (0 字节)
├── p_pref_qc_camera_iso_key_0               (0 字节)
├── p_pref_qc_camera_pro_exposure_value_key_0 (0 字节)
├── p_pref_camera_manually_lens_wide         (0 字节)
├── p_pref_camera_zoom_retain_key_1.0        (0 字节)
├── p_pref_camera_whitebalance_key_new_1     (0 字节)
├── p_pref_focus_position_key_1000           (0 字节)
├── p_pref_qc_camera_style_tone_key_-18      (0 字节)
├── p_pref_qc_camera_style_color_temp_key_-10 (0 字节)
├── p_pref_qc_camera_style_color_tone_key_-5 (0 字节)
├── p_pref_qc_camera_style_vibrance_key_5    (0 字节)
├── p_pref_qc_camera_style_texture_key_-15   (0 字节)
├── p_pref_camera_raw_key_JPEG               (0 字节)
├── p_pref_ultra_pixel_167_OFF               (0 字节)
├── t                                        (0 字节)
├── v_3                                      (0 字节)
└── ac                                       (0 字节)
```

键名格式统一为 `键名_key_值`。解析方式：取 `_key_` 之后的部分作为值。

## 二、文件名规则

```
Manual _ 作者名 _ 时间戳 _ 预设名 .zip
  类型     谁做的    什么时候   叫什么
```

| 部分 | 是否必须 | 说明 |
|---|---|---|
| `Manual_` 前缀 | **必须** | 决定相机的解析类型，删掉会导致不识别 |
| 作者名 | 任意 | 相机忽略 |
| 时间戳（13 位毫秒） | 任意 | 相机忽略，仅用于避免同名覆盖 |
| 预设名（最后一段） | **必须** | 相机取最后一段作为界面显示名 |

**实测结论：**

- 相机只取最后一段中文作为显示名，前缀、作者、数字全部跳过
- 文件名里的数字对相机没有任何意义，既不当 ID 也不当排序依据
- 导入后相机自己按顺序重新编号（C1、C2、C3…），与文件名无关
- 单次导入上限约 15 个

## 三、前缀与格式版本

| 前缀 | 版本 | 含义 |
|---|---|---|
| `Manual_` | `v_3` | 完整预设，可同时承载专业参数和风格五项 |
| `Manual_` | `v_2` | 旧式纯风格预设，只有风格五项 |
| `Style_` | `v_2` | 纯风格预设，**实测样本中 100% 为 v_2** |

想让预设同时包含 ISO/快门/白平衡和风格，**必须用 `Manual_` + `v_3`**。

**实测：`Style_`(v_2) 与 `Manual_`(v_3) 的数值等价。** 官方「大师水墨」「古典胶片」「高对比经典」「暗调电影」在社区包的 `Style_official_*` 和官方包的 `Manual_xuanyuan_*` 里五项数值完全相同，只是键数不同（18 vs 19）。v_2 / v_3 只决定「带不带专业参数」，不改变风格本身的含义。

## 四、风格五项

范围 **−50 ~ +50** 整数。

| 键 | 界面名称 | 说明 |
|---|---|---|
| `p_pref_qc_camera_style_tone_key` | 对比度 | 负值平淡，正值硬朗 |
| `p_pref_qc_camera_style_color_temp_key` | 冷暖调 | 负值偏青蓝，正值偏暖黄 |
| `p_pref_qc_camera_style_color_tone_key` | 青品调 | 负值偏青绿，正值偏品红 |
| `p_pref_qc_camera_style_vibrance_key` | 饱和度 | −50 时画面变黑白 |
| `p_pref_qc_camera_style_texture_key` | 锐度 | 负值柔化，正值锐利 |

界面显示顺序与上表顺序一致，已通过导入后逐项核对确认。

### 官方参数域

16 组官方预设实际用到的范围，可作为合法取值的参考：

| 参数 | 官方实际范围 | 理论上限 |
|---|---|---|
| 对比度 | −37 ~ +50 | ±50 |
| 冷暖调 | −32 ~ +36 | ±50 |
| 青品调 | −25 ~ +50 | ±50 |
| 饱和度 | −50 ~ +35 | ±50 |
| 锐度 | −20 ~ +50 | ±50 |

官方对极值极其克制：+50 全库只用过 3 次，−50 只用在两组黑白预设的饱和度上。

### 黑白的实现方式

zip 里没有任何「黑白开关」。官方两组黑白预设的做法：

| 名称 | 对比度 | 冷暖 | 青品 | 饱和度 | 锐度 |
|---|---|---|---|---|---|
| 高对比黑白 | +50 | 0 | 0 | **−50** | +36 |
| 柔和黑白 | −35 | 0 | 0 | **−50** | +35 |

**饱和度 −50 + 冷暖/青品归零 + 锐度 +35，硬调柔调只差对比度。** 这就是官方做法。

## 五、专业模式参数

| 键 | 取值 | 说明 |
|---|---|---|
| `p_pref_camera_cv_type_key` | 1 / 0 | 含义未确定，样本中 1 占多数 |
| `p_pref_camera_autoexposure_key` | 1 / 0 / 2 | 含义未确定，样本中 1 占多数 |
| `p_pref_qc_camera_exposuretime_key` | 纳秒整数，**0 = 自动** | 见下方快门规则 |
| `p_pref_qc_camera_iso_key` | 整数，**0 = 自动** | 样本中出现 0 和 200 |
| `p_pref_qc_camera_pro_exposure_value_key` | EV，如 `-0.7` | 0 表示不补偿 |
| `p_pref_camera_whitebalance_key_new` | 色温 K 值，**1 = 自动** | 样本中出现 1/3950/4000/4700/5000/5200 |
| `p_pref_camera_manually_lens` | `wide` / `tele` / `Standalone` | 镜头 |
| `p_pref_camera_zoom_retain_key` | `1.0` / `3.0` / `5.0` | 变焦倍率 |
| `p_pref_focus_position_key` | 恒定 `1000` | 对焦位置，样本中全部相同 |
| `p_pref_camera_raw_key` | `JPEG` | 样本中只出现 JPEG |
| `p_pref_ultra_pixel_167` | `OFF` / `BYPASS` | 超像素开关 |
| `p_pref_camera_pro_aperture_key` | 如 `-1.0` | 仅可变光圈机型出现 |

### 快门规则（实测）

快门以**纳秒**存储，但**必须是 1000 的整数倍**，即换算成微秒后不能有小数。否则该字段被静默忽略，界面回落显示「A」（自动）。

| 写入值（ns） | 微秒 | 档位 | 结果 |
|---|---|---|---|
| 2000000 | 2000 | 1/500 | 有效 |
| 800000 | 800 | 1/1250 | 有效 |
| 5000000 | 5000 | 1/200 | 有效 |
| 500000000 | 500000 | 0.5s | 有效 |
| **714286** | **714.286** | 1/1400 | **失效，回落自动** |

推论：相机内部以微秒为快门单位。分母不能整除 1000 的档位（1/1400、1/640、1/60、1/30、1/15 等）本质上无法表达，只能取最接近的可表达值。

### 键名容错

同一个参数存在两种拼写，且都能用，甚至有包同时包含两个：

- `p_pref_camera_ultra_pixel_167_BYPASS`
- `p_pref_ultra_pixel_167_BYPASS`

说明相机对键名匹配不严格，或做了兼容处理。

### 缺字段容错

48 个社区样本里有 14 个**完全没有 `vibrance` 键**，照样能导入。说明该字段是后期版本新增的，缺失不影响。

## 七、二进制结构（字节级）

如果需要用代码生成（而不是靠现成库），必须复刻以下结构才能让相机正确识别。生成器的纯 JS 实现与官方打包结果**逐字节一致**。

每个条目的布局：

```
本地文件头 30 字节
  signature      04 03 4b 50   (PK\x03\x04, 小端)
  version        14 00
  flags          08 08         (0x0808 = data descriptor + UTF-8 文件名)
  method         08 00         (deflate)
  modtime/date                  (MS-DOS 格式)
  crc32          00000000      (flag 0x0808 下填 0)
  csize/usize    00000000      (填 0，真实值在 data descriptor 里)
  namelen/extra  <名字长度> 0000
文件名（UTF-8）
数据            03 00         (空内容的 raw deflate 块，2 字节)
data descriptor 16 字节
  07 08 4b 50   (PK\x07\x08)
  crc32 00000000
  csize 02000000  (2)
  usize 00000000
```

中央目录项 46 字节 + 文件名，其中 `csize = 2`、`usize = 0`、`external_attr = 0`、`creator_version = 0x0014`。

EOCD 无注释。

**验证方式：** 用上述结构重新打包任一样本，输出应与原文件字节完全相同。本项目生成器已通过此验证（2890 / 2890 字节完全一致）。

## 八、能做到与做不到

| 项目 | 能否通过 zip 预设控制 |
|---|---|
| 对比度 / 冷暖调 / 青品调 / 饱和度 / 锐度 | ✅ |
| 曝光补偿 EV | ✅ |
| 白平衡色温 | ✅ |
| ISO / 快门 / 对焦位置 | ✅ |
| 镜头（主摄/长焦）与变焦倍率 | ✅ |
| RAW / 超像素开关 | ✅ |
| **滤镜**（正片、负片、远山青等） | ❌ 官方 16 组里无一包含滤镜键 |
| **摄影风格**（徕卡经典 / 徕卡生动） | ❌ |
| **测光模式** | ❌ |
| **曝光/亮度/光感/高光/阴影** | ❌ 相机内没有这些控件（属相册后期参数） |

滤镜与摄影风格是相机的全局设置，与预设相互独立。导入预设不会改变它们。

## 九、二维码分享格式（不可解析）

部分预设通过二维码分享，内容为：

```
micamera://open?foreground_input=<470 字符 URL-safe base64>
```

这是**加密载荷**，无法离线解析，也无法自行生成：

| 检测项 | 结果 |
|---|---|
| 解码长度 | 固定 352 字节 |
| 香农熵 | 7.41 ~ 7.47 bit/byte（接近随机上限 8） |
| 内部重复 16 字节块 | 0（非 ECB 模式） |
| gzip / zlib / lzma / bz2 | 全部失败 |
| protobuf 试探 | 立即遇到非法 wiretype |
| 首 16 字节 | 出现两两相同（固定 IV + 首块含分组信息） |

密钥在相机 App 内部。**结论：二维码只能扫，不能造。** 想要自定义分享，只能走 zip。

另外，二维码预设可以携带**滤镜**和**测光模式**，这是 zip 格式不具备的能力。也就是说二维码是比 zip 更完整的一种分发方式，但它是加密的、封闭的。

## 十、未确定项

以下是分析中无法确证的部分，已知就写，不猜：

1. `t` / `ac` 两个标记文件的作用
2. `v_2` / `v_3` 是否真的是格式版本号（结构对应，但无文档）
3. `cv_type` / `autoexposure` 两个键的确切含义
4. 相机是否有样本未覆盖到的隐藏校验字段
5. 官方参数域之外的极端值（如对比度 −50）是否会产生异常
6. 其他机型（12S / 13 / 14 / 15 / 16）是否完全一致

## 十一、如何自行验证

改了参数不确定有没有生效时，按这个顺序查：

1. 导入后看预设列表里的五项数值是否与写入值一致 → 验证结构正确
2. 进专业模式看 ISO / 快门 / WB 显示值 → 验证编码正确
3. 若快门显示「A」而你没填 0 → 检查纳秒值是否为 1000 的整数倍
4. 若整个包导入失败 → 检查文件名前缀是否为 `Manual_`，条目数是否为 19
